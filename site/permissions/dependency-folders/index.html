Dependency and Git folders

OptionalAsked inside Artifact Atlas

What it is

A choice about what a scan counts, made inside Artifact Atlas. It is asked before the first scan of a real application and can be changed at any time in the Permissions window. It is off until you turn it on.

Which folders

Inside project folders, these are skipped by default: node_modules, bower_components, .pnpm-store, .git, .hg, .svn, .venv, venv, Pods and .gradle. Folders that belong to the application itself are always scanned in full.

What happens when they are included

Each such folder is measured as a whole: its files are counted and their size is added to the total, but none of them is listed. On the map they appear under one mark, Dependencies & Git (measured), which opens by project and then by folder. Files shared through hardlinks (as pnpm does) are counted once.

Because they are not listed, they do not use up the limit of 300,000 listed files per scan, and nothing in them can be selected or moved to Quarantine.

Why they are left out by default

  • Measuring them still means visiting every file, which can make a scan much slower.
  • Nothing in them should be removed one file at a time. Dependencies are reinstalled by your package manager; Git data is your history.

When they are left out, they are not read at all, and the scan tells you how many such folders it skipped.

When to include them

Include them when you want the total to match what the project folders occupy on disk. It has an effect only where a project folder is walked: with whole project folders included, or for a folder you scan yourself.

What never happens

  • Nothing inside a measured folder is offered for cleanup. Remove dependencies with your package manager and Git data with Git.
  • Folders that belong to the application itself are not affected: they are always listed in full.

How to change it

  1. Open Permissions in the top bar.
  2. Under What a scan counts, click Include or Leave Out on Dependency and Git folders.
  3. Scan the application again.
